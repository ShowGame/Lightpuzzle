## 一、目标与风控

在**益智 / 烧脑 / 推箱子 / 解谜 / 游戏推荐**类帖子下，以「同好安利」口吻自然提及 **小咪的光学迷宫**（微信小游戏），降低硬广感与被举报风险。

| 原则 | 说明 |
|------|------|
| 只发文字 | 当前 skill 不支持评论带图 |
| 不重复触达 | 同一帖子、同一作者只进入一次（见已回复记录）；单帖内楼中楼只回**精选**评论，不随机 |
| 聚焦关键词 | 不对无关帖子评论 |
| 仅新帖 | 只评论 **60 天内** 发布的笔记 |
| 频率控制 | 建议同一账号间隔 **≥30 分钟** 再发下一条 |
| 人工复核 | 发前确认帖子语境匹配，避免引战帖、广告帖 |

**风险提示**：自动化评论存在被平台限流、封号风险；优先用小号测试，控制规模。

### 轮播策略

1. 从 `推广语轮播.json` **按语义**选最贴切的一条（`rotation.mode: semantic`）
   - 一级评论：匹配 **帖子标题 + 搜索关键词**
   - 楼中楼：匹配 **帖子标题 + 被回复评论正文**（§3.1 实现后）
   - 每条文案有 `category` + `matchKeywords`；脚本叠加分类信号打分，同分随机
   - 最近 20 条内尽量不重复同一 `messageId`；无信号时降级随机
2. 检查 `已回复记录.json`：该 `feed_id` 或 `author_id` 已存在则跳过
3. 按 **§3.1 单帖流程** 执行（一级评论 → 精选楼中楼）
4. 写入记录（含 `messageCategory`、`matchScore` 便于复盘）

> **Agent 介入**：脚本负责「选哪条模板」；楼中楼若需接语境改写，由 Agent 在模板基础上微调，不要原样粘贴。

### 3.1 单帖评论流程（后续执行标准 · 必遵）

> 试跑阶段仅做了一级评论；**以后每进一个新帖**按下列顺序，**禁止随机挑评论回复**（易被举报）。

**Step 1 · 先发一级评论**

- 用 `post-comment-to-feed` 在帖子下留 1 条（轮播文案）
- 语气像同好分享，不要硬广

**Step 2 · 拉取评论区**

- `get-feed-detail --load-all-comments` 读取评论列表
- 了解帖子在讨论什么（求推荐 / 推箱子 / 微信小游戏 / 卡关等）

**Step 3 · 精选楼中楼目标（不随机）**

只回复 **与帖意、与《小咪的光学迷宫》最贴合** 的评论，例如：

| 优先回复 | 示例 |
|---------|------|
| 求推荐 / 求同类游戏 | 「有没有类似的解谜游戏？」 |
| 推箱子 / 烧脑 / 益智 | 「推箱子玩腻了求新作」 |
| 微信小游戏 / 碎片时间 | 「有没有不用下载的小游戏」 |
| 纯解谜、不要恐怖 | 「想要无剧情纯逻辑的那种」 |

**不要回复**：

- 与游戏无关的闲聊、玩梗、吵架
- 明显广告/引流评论
- **随机抽一条**就回（像机器人，举报风险高）

**Step 4 · 楼中楼数量**

- 上限：`ceil(总评论数 × 5%)` ～ `ceil(总评论数 × 10%)`（向上取整）
- 评论很少的帖：最多 1 条楼中楼，且**不要**把每条评论都回一遍
- 回复文案要 **接对方语境**（可改写轮播语，不要原样粘贴）

**Step 5 · 记录**

- 一级 + 楼中楼均写入 `已回复记录.json`
- 楼中楼建议额外记 `targetCommentId` / `targetCommentSnippet`（待脚本扩展）

## 四、已回复去重记录

`已回复记录.json` 单条记录字段：

```json
{
  "feedId": "笔记ID",
  "feedTitle": "笔记标题",
  "authorId": "作者userId",
  "authorNickname": "作者昵称",
  "keyword": "搜索关键词",
  "messageId": 2,
  "messageText": "发出的评论原文",
  "commentedAt": "2026-07-18T15:30:00+08:00"
}
```

**去重规则**：

- `feedId` 已存在 → 不再评论该帖
- `authorId` 已存在 → 不再评论该作者任意帖（避免同一人被多次触达）

**限速计数（帖数，非评论条数）**：

- `--target` / `--count`：本次要触达的 **帖数**
- `100 帖/天`：统计 **不同 `feedId`**；同一帖内 1 条一级 + N 条楼中楼仍只计 **1 帖**（`maxPerHour: 0` 表示不限小时）
- 帖与帖之间间隔 **3～5 分钟**；帖内楼中楼用 **30 秒～2 分钟**（待脚本实现 §3.1）

## 五、运营模式：脚本跑量 + Agent 偶尔介入

> **默认采用此模式**：日常由脚本自动发一级评论（**0 Token**）；Agent 只在关键节点介入（**约 1～2 万 Token/天**）。

### 分工

| 角色 | 负责 | Token |
|------|------|-------|
| **脚本** | 搜索、筛选、轮播文案、一级评论、去重、限速、熔断 | ≈ 0 |
| **Agent** | 启动/监控、看汇总、精选帖做楼中楼、改文案、处理异常 | 偶尔 |

### 推荐日程（100 帖/天上限）

| 时段 | 动作 | 谁执行 |
|------|------|--------|
| 早/午/晚 各 1 次 | `python run_comment_campaign.py --count 8`（挂后台，3～5 分钟/帖） | 脚本 |
| 全天 | 脚本自动写 `已回复记录.json`，Agent **不必每条守着** | 脚本 |
| 每天 1～2 次 | Agent 打开记录，挑 **5～10 条高相关帖**（求推荐/解谜类）做楼中楼 | Agent |
| 熔断/失败 | 看 `circuitBreakerUntil`，Agent 排查或停跑 | Agent |

### Agent 介入触发条件（满足任一才叫 Agent）

1. 脚本 SUMMARY 里 `failures > 0` 或退出码 `3`（熔断）
2. 你想对某条 **高互动帖** 做精选楼中楼（§3.1）
3. 要调整关键词 / 限速 / 推广语
4. 小号出现验证码、发评连续失败

### Agent 介入时怎么说（示例）

```
帮我跑 8 个帖，脚本后台执行即可，做完给我 SUMMARY。
```

```
看已回复记录里「求推荐解谜」的帖，选 3 条做楼中楼，不要随机，接语境改文案。
```

### Token 预估（此模式）

| 项目 | 约消耗 |
|------|--------|
| 脚本跑满 100 帖/天 | **0** |
| Agent 启动 3 次 + 看汇总 | **5k～10k/天** |
| Agent 精选 10 帖楼中楼 | **+1～3 万/天** |
| **合计** | **约 1～4 万 Token/天** |

## 六、自动执行脚本

```powershell
cd 宣传素材/小红书评论

# 试跑 N 条（会写入 已回复记录.json）
python run_comment_campaign.py --target 10

# 仅补发若干条
python run_comment_campaign.py --count 1

# 只看候选、不发评
python run_comment_campaign.py --target 10 --dry-run
```

### 筛选规则（脚本内置）

| 规则 | 说明 |
|------|------|
| 60 天内 | 按 `cornerTagInfo.publish_time` 过滤 |
| 相关度 | 标题含益智/烧脑/推箱/解谜等；排除恐怖/肉鸽/带货等 |
| 去重 | 同一 `feedId` / `authorId` 不重复 |
| 搜索策略 | **按需逐词、单次跳转**：直接打开 `make_search_url(keyword)`；当前 tab 已是同一关键词则 **0 次跳转**（不再连跳空白搜索页 + 下拉推荐 API） |
| 候选耗尽 | 6 个词都搜完仍无新帖则停止（不再连刷 21 词） |
| 低评论帖 | 评论数 ≤10 的帖，每轮搜索最多触达 3 条，避免刷屏 |
| 楼中楼配额 | `ceil(评论数 × 5%)` 为单帖二级回复上限（当前试跑用一级评论） |
| 间隔 | 帖与帖 **3～5 分钟**；**仅在下一次搜索前** 等 **5～15 秒**（不是连刷所有关键词） |
| 频率上限 | 默认 **100 帖/天**（无小时上限；`maxPerHour: 0`；按 `feedId` 去重） |
| 失败熔断 | 发评失败 → **停 24 小时**（写入 `已回复记录.json` → `circuitBreakerUntil`） |
